## Observations

| Kind | Where | What |
| --- | --- | --- |
| status | /admin/sources | Parsing is synchronous: the form sits on 'Ne zatvarajte stranicu' until the model answers, with no progress and no way to queue it. |
| clicks | /admin/sources/[id] | Every candidate arrives collapsed to a one-line summary; its fields and its Kreiraj/Ignoriraj buttons do not exist until it is expanded — one extra click per candidate, before any work. |
| clicks | /admin/sources/[id] | The work starts 1037px down a 900px viewport: the source summary and the full "Dopuni i ponovno parsiraj" panel (a textarea plus a four-image dropzone) sit above "Parsirani kandidati", so every visit begins by scrolling past tools that are rarely used. |
| memory | /admin/sources/[id] | The source's own text is behind a collapsed 'Neobrađeni tekst izvora' panel, so checking a parsed date against the source means opening it, reading, and holding the date in mind while scrolling back to the candidate. |
| clicks | candidate card | Expanding does not widen the card: it stays 568px inside a 1152px two-column grid, with the neighbouring column left blank. Half the screen is unused while the card is twice as tall as it needs to be. |
| retyping | candidate card | One candidate carries 4 overlapping location fields (Grad, Lokacija / venue, Adresa, Precizna lokacija (koordinate)). The editor has to work out which one the public page will use, and keep them consistent by hand. |
| clicks | candidate card | An expanded candidate is 2 viewports tall at 1440x900, and its Kreiraj / Ignoriraj footer is at the bottom — so every candidate is expand, scroll down the card, act, scroll back up. |
| clicks | candidate card | Categories are a 16-checkbox grid inside the card; picking one means scrolling the card and clicking, with no search and no keyboard shortcut. |
| status | candidate card | 'Kreiraj događaj' creates the event as PENDING_REVIEW (admin.service.ts:952), so the editor who just reviewed the candidate has to review the same event a second time in /admin/events/pending. 'Kreiraj i objavi' publishes outright. The two buttons sit side by side and nothing on screen says that the first one doubles the work. |
| status | candidate card | A missing field shows as a 'Nedostaje: city' badge, but the field it refers to is not highlighted or focused — the editor has to find it. |
| a11y | /admin/events/new | Schedule and basic fields are labelled by a <Label> with no htmlFor and inputs with no id, so the label is visible but not programmatically associated — a screen reader reads an unlabelled field, and getByLabel cannot find it. The 'Naziv' field has no placeholder either, so it has no accessible name at all. |
| combinable | /admin/events/new vs /admin/events/[id] | The create form picks a city from a dropdown plus a free-text 'Novi grad' box; the edit form uses the geocoding autocomplete instead. Two different mental models for the same field. |
| clicks | /admin/events and /admin/sources/[id] | Bulk actions exist on the events table (select rows, then category / status / shift dates / delete) and on the pending queue, which shares that table — but not on parsed candidates, where the volume actually is. A source with eight candidates has to be worked one card at a time. |
| state-loss | /admin/events/[id] | The form has no unsaved-changes guard: navigating away or following a breadcrumb discards every edit silently. |
